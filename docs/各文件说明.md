# 各源代码文件说明（答辩用）

> 本项目一共 **6 个源文件**，合计 **2477 行**（其中代码约 2000 行，其余是空行和注释）。
> 每个文件干什么、里面有哪些函数、老师可能问什么，都写在下面。

## 0. 一分钟总览

| 文件 | 行数 | 干什么 |
|---|---|---|
| `src/structs.h` | 229 | **公共头文件**。定义所有结构体、常量、全局变量、函数声明 |
| `src/data.cpp` | 517 | **数据层**。读 8 个 txt 文件、日期计算、各种查找和统计 |
| `src/graph.cpp` | 141 | **图的算法**。用邻接矩阵存平面图，用 Dijkstra 求最短路 |
| `src/logic.cpp` | 515 | **业务逻辑**。导诊、挂号、取消、签到、叫号、停诊通知、评价、转诊 |
| `src/ui.cpp` | 1024 | **图形界面**。8 个页面的绘制和点击处理（极简风格：只有方框和文字） |
| `src/main.cpp` | 51 | **主函数**。读数据 → 打印统计 → 打开界面 |

调用关系很简单，就是一条直线：

```
main.cpp  →  data.cpp（先把数据读进来）
              ↓
           ui.cpp（画界面、响应点击）
              ↓
           logic.cpp（真正干活：导诊、挂号、排队……）
              ↓
           graph.cpp（算路线的时候用）
```

## 1. `structs.h` —— 公共头文件

### 作用
所有文件都要 `#include "structs.h"`，它是整个程序的"总目录"。

### 里面有什么

**① 常量（`#define`）**
```c
#define MAX_DEPT     20     /* 科室最多 20 个 */
#define MAX_DOCTOR   60     /* 医生最多 60 个 */
#define MAX_SCHEDULE 400    /* 排班最多 400 条 */
...
```
用宏定义数组的最大长度，因为 C++ 的静态数组长度必须是编译时确定的常量。

**② 10 个结构体**

| 结构体 | 对应什么 | 主要字段 |
|---|---|---|
| `Dept` | 科室 | 编号、名称、位置、楼层、简介、常见症状 |
| `Doctor` | 医生 | 编号、姓名、科室、职称、擅长、挂号费、评分、**诊室节点号** |
| `Schedule` | 排班 | 编号、医生、日期、时段、最多几个、已约几个、状态 |
| `Patient` | 患者 | 编号、姓名、性别、年龄、手机、密码 |
| `Appointment` | 预约 | 编号、患者、医生、排班号、第几号、状态 |
| `Evaluation` | 评价 | 编号、患者、医生、分数、内容 |
| `Symptom` | 症状—科室关联 | 症状词、科室、**关联强度（就是二部图的边权）** |
| `MapNode` | 平面图节点 | 编号、楼层、名称、类型、坐标 |
| `QueueItem` | 候诊队列项 | 预约号、优先级 |
| `Notice` | 通知 | 患者、内容 |

**③ 全局变量（用 `extern` 声明）**
所有数据都放在全局数组里，比如 `depts[]`、`doctors[]`。真正的定义在 `data.cpp`。

**④ 函数声明**
把其他几个 .cpp 里的函数都声明一遍，这样任何文件都能调用它们。

### 老师可能问
- **问：为什么把这些放在头文件里？**
  答：因为好几个 .cpp 都要用同一批结构体和函数，放在头文件里各文件 include 一次就行，避免重复定义。
- **问：`extern` 是什么意思？**
  答：`extern int deptNum;` 只是"声明"有个这样的变量，真正的内存分配在 data.cpp 里（要写 `int deptNum = 0;`）。这样多个文件都能用同一个变量。
- **问：为什么用 `#define` 不用 `const`？**
  答：用 #define 是习惯写法，而且数组长度用宏最直观。

## 2. `data.cpp` —— 数据层

### 作用
程序一启动就调用这里的 `loadData()`，把 `data/` 目录下 8 个 txt 文件读进内存数组。

### 主要函数

**① 读文件相关的工具函数**

| 函数 | 作用 |
|---|---|
| `utf8ToGbk(char* s)` | **把 UTF-8 的中文转成 GBK**。数据文件是 UTF-8 存的，但程序里的中文和 EasyX 显示都按 GBK，不转的话界面全是乱码 |
| `trim(char* s)` | 去掉行尾的 `\r\n` 和空格 |
| `split(...)` | 按 `|` 把一行拆成几个字段 |
| `readLine(...)` | 读一行有效数据，自动跳过空行、`#` 注释行和文件开头的 BOM |
| `openData(char* name)` | **按名字打开 `data` 下的文件**，先试 `data/xxx.txt`，再试 `../data/xxx.txt`，都打不开就返回 `NULL` |

**② 日期函数**

| 函数 | 作用 |
|---|---|
| `isLeap(int y)` | 判断闰年 |
| `monthDays(int y, int m)` | 某年某月有多少天 |
| `addDays(int dateNum, int n)` | 日期加减 n 天（`20261011` 这种整数形式） |
| `weekDay(int dateNum)` | 用**基姆拉尔森公式**求星期几，返回 0=周一 … 6=周日 |
| `realDate(src, out)` | 把数据文件里的 `TODAY+1` 换成真正的日期 |

> **为什么要 `TODAY` 占位符？** 因为如果数据文件里写死日期，过几天程序再跑，"可预约的日期"就全变成过去的了，演示不了。用 `TODAY+1` 程序会自动换成今天和明天的日期，数据永远不会过期。

**③ 8 个读文件的函数**
`loadDept` / `loadDoctor` / `loadSchedule` / `loadPatient` / `loadAppointment` / `loadEvaluation` / `loadSymptom` / `loadMap`，每个都是"打开文件 → 循环读一行 → 拆字段 → 存进数组"。它们都用 `openData()` 打开文件，而不是直接写 `fopen("data/xxx.txt")`。

> **为什么要 `openData()`？** 因为程序运行时的工作目录不一定是项目根目录。如果直接双击 `build\hospital.exe`，工作目录是 `build\`，这时 `data/department.txt` 是找不到的。`openData()` 先按 `data/xxx.txt` 找，找不到再按 `../data/xxx.txt` 找一层，这样从项目根目录运行、从 `build` 目录运行都能正常读到数据。

**④ `loadMap()`**
平面图文件里一行可能是节点（以 `N` 开头）也可能是边（以 `L` 开头），所以用 `strcmp` 判断一下。边是**无向边**，所以 `graph[a][b]` 和 `graph[b][a]` 都要存。

**⑤ 查找函数**
`findDept` / `findDoctor` / `findPatient` / `findSchedule` / `findAppointment`，都是**顺序查找**（从头到尾 `strcmp` 比较），返回数组下标，找不到返回 -1。

**⑥ 统计函数**
`remainSeat()` 算某条排班还剩几个号，`deptDoctorNum()` 算科室有几个人，`deptAvgScore()` 算科室平均分。

### 老师可能问
- **问：数据是怎么存的？**
  答：全部放在全局数组里。科室 12 个、医生 36 个、排班 264 条，都是静态数组，读文件的时候一边读一边往数组里放，用 `deptNum`、`doctorNum` 这些变量记个数。
- **问：查找为什么不用二分？**
  答：数据量小（最多几百条），顺序查找就够快了，实现也简单。如果数据量大可以先把数组按编号排序，再用二分查找，这样是 O(log n)。
- **问：为什么要中文转码？**
  答：txt 文件是 UTF-8 存的，但程序编译时用了 `-fexec-charset=GBK`，字符串常量是 GBK 的，EasyX 显示中文也按 GBK。两边编码不一样，中文会乱码，所以在读进来的时候统一转一次。
- **问：`TODAY` 是怎么实现的？**
  答：`realDate()` 里判断字符串前 5 个字母是不是 "TODAY"，是的话就取后面的 `+n` 或 `-n`，用 `addDays` 算出真日期。
- **问：为什么要有 `openData()` 这个函数？**
  答：因为程序的工作目录不一定是项目根目录。一开始我直接写 `fopen("data/department.txt")`，在根目录下运行没问题，但双击 `build\hospital.exe` 时工作目录是 `build\`，就报"数据读取失败"。后来改成用 `openData()` 先试 `data/xxx.txt`，再试 `../data/xxx.txt`，两种情况都能跑。这也是我写在开发日志里的一个 bug。

## 3. `graph.cpp` —— 平面图和最短路径

### 作用
就诊楼有 6 层，每层平面用一个图来表示：**节点**是走廊、诊室、电梯、楼梯；**边**是节点之间的路。用**邻接矩阵**存，`graph[i][j]` 存距离，0 表示不通。求路线用 **Dijkstra 算法**。

### 主要函数

| 函数 | 作用 |
|---|---|
| `gateNode()` | 找门诊大门节点（type==4） |
| `findRoomNode(doctorId)` | 找某个医生的诊室节点 |
| `nodeName/nodeFloor/nodeType(id)` | 根据编号查节点的名字、楼层、类型 |
| `shortestPath(start, end, path, len)` | **Dijkstra 求最短路**，返回总距离，`path` 里存路径 |
| `pathToText(path, len, out, size)` | 把路径翻译成"1. 沿走廊走到门诊大厅（20米）"这样的文字 |

### Dijkstra 是怎么写的（重点，老师一定会问）

```c
dist[] 记录起点到每个点的当前最短距离，一开始除起点外都是 -1（表示没算出来）
visited[] 记录哪些点已经确定是最终答案了

重复做下面两步，直到所有点都确定或者终点确定了：
  1. 在还没确定的点里，找一个 dist 最小的，记作 u
  2. 用 u 去"松驰"它周围的点：如果 dist[u] + 边长 < dist[v]，就更新 dist[v]
最后从终点倒着往回找 prev[]，把路径翻过来
```

**时间复杂度是 O(V²)**（因为每次找最小点都要把所有点扫一遍）。本项目节点只有 58 个，58² 才 3364 次操作，完全够快。

> 如果想更快，可以像标准写法那样用一个**最小堆**来选最小点，复杂度降到 O((V+E)logV)。这个可以作为改进方向讲。

### 老师可能问
- **问：图为什么要用邻接矩阵？不用邻接表？**
  答：节点只有 58 个，邻接矩阵是 120×120 的二维数组，占内存很小；而且判断两个点之间通不通只要写 `graph[i][j]`，是 O(1)，Dijkstra 里要用到这个。如果节点有成百上千个，就用邻接表更省内存。
- **问：跨楼层怎么走的？**
  答：电梯和楼梯各有一串节点（一层电梯连二层电梯，二层连三层……），边上的权是固定的 5 米。这样不同楼层就被连成了一张图，Dijkstra 能算出"坐电梯上 3 楼再走过去"这种路线。
- **问：`pathToText` 里的 "坐电梯" 是怎么判断的？**
  答：`edgeKind[a][b]` 存了这条边的类型，0 是走廊、1 是电梯、2 是楼梯，根据这个选不同的说法。
- **问：如果两个点之间不通怎么办？**
  答：`shortestPath` 里如果终点始终没被确定（`dist[end] < 0`），就返回 -1，界面上提示"没有找到路线"。

## 4. `logic.cpp` —— 业务逻辑（最核心的文件）

### 作用
所有"真正干活"的函数都在这里：导诊、挂号、取消、签到、叫号、停诊通知、评价、转诊。

### 分块说明

**① 智能导诊 `doTriage()`**

这是整个系统最"算法"的部分。把**症状和科室看成一个加权二部图**：症状在一边，科室在另一边，边上的权是关联强度。步骤：

```
1. 在患者输入的描述里逐个找症状关键词（自己写的简单匹配 findWord）
   找到了就把这条边的权加到对应科室的得分上
2. 如果一个关键词都没认出来，就拿输入的文字和科室的"常见症状"做简单比对
3. 加上评分加成（最多 1.5 分）和号源加成（最多 1 分）
4. 找出最高分，把每个科室的得分换算成百分制的"匹配度"
5. 用选择排序从高到低排，取前 8 个输出
```

**② 转诊推荐 `recommendTransfer()` + `deptSimilar()`**

把每个科室看成"症状权重"组成的一个向量，两个科室的相似度用**余弦相似度**算：

```
sim(A,B) = (A·B) / (|A| × |B|)
```

某科室号源紧张的时候，就推荐**相似度高、而且还有号**的科室。

**③ 预约挂号 `bookAppoint()`**

严格按顺序检查，任何一步不通过就返回错误码：

```
患者存在？→ 排班存在？→ 医生没停诊？→ 还有号？→ 日期没过去？→ 没重复预约？
全过了才 booked++（扣号），然后新建一条预约记录
```

**错误码**：0 成功、3 停诊、4 满了、5 重复预约、6 日期已过。界面上根据错误码给出不同的中文提示。

**④ 候诊队列（重点）**

用了一个**有序数组**来实现优先队列：

- `queueInsert(apptId, priority)`：**按优先级插入到合适的位置**（从后往前比，比它优先级低的往后挪）。这样数组的第 0 个永远是最该先看的人。
- `queueRemoveAt(idx)`：叫号后把这个人从数组里删掉，后面的往前挪。
- `queuePriority()`：**年龄 ≥ 65 岁的患者优先级是 2，普通人是 3**，数字小的先看 —— 这就是"老年人优先"。
- `callNext()`：从第 0 个开始找，找到指定医生的第一位患者，取出来，状态改成"就诊中"。

**⑤ 停诊通知 `suspendSchedule()`**

把一条排班的状态改成"停诊"，然后遍历所有预约，把这条排班下"已预约/已签到"的患者全部改成"停诊退号"（状态 6），并且**每人发一条通知**，最后把号源退回去。

**⑥ 评价 `addEvaluation()`**

只能评价"已完成"的就诊；同一个患者对同一个医生只算一次；提交后**立刻重算这个医生的平均分**。

**⑦ 预约凭证 `buildReceipt()`**

用 `sprintf` 拼一段多行文字，里面有预约号、患者、科室、医生、日期、时段、序号、诊室、费用、状态。

### 老师可能问
- **问：导诊的匹配度是怎么算的？**
  答：先把命中的症状关键词对应的边权加起来得到基础分，再加上医生评分加成和号源加成，最后除以最高分换算成百分比。所以第一名的匹配度一定是 100%。
- **问：为什么用二部图？**
  答：因为"症状"和"科室"是两类不同的东西，一个症状可能对应多个科室，一个科室也有多个常见症状，正好是二部图的结构，边权表示关联强弱，题目提示里也是这么建议的。
- **问：候诊队列为什么不用真的优先队列（堆）？**
  答：患者数量很少（同时最多几十个人），用有序数组插入就够了，插入是 O(n)，取出是 O(1)，实现简单也好理解。如果人多，可以用堆，插入和取出都是 O(log n)。
- **问：怎么保证不会超订？**
  答：`bookAppoint` 里是先检查 `remainSeat(sIdx) <= 0` 才 `booked++` 的，检查和扣号是在同一个函数里顺序执行的，中间不会被打断，所以不会超订。
- **问：老年人优先是怎么实现的？**
  答：签到的时候根据患者年龄算出优先级（≥65 岁是 2，其他人是 3），插入队列时按优先级插到对应位置。

## 5. `ui.cpp` —— 图形界面

### 作用
用 EasyX 画出 8 个页面，并处理鼠标点击。窗口是 1024×700。

### 8 个页面

| 序号 | 页面 | 内容 |
|---|---|---|
| 0 | 首页 | 数据统计、系统功能说明、切换患者、立即导诊 |
| 1 | 智能导诊 | 输入症状、常用症状快捷按钮、推荐科室列表（科室名 + 匹配度百分比） |
| 2 | 科室预约 | 左边科室列表、右边医生列表、下面可预约时段，点"确认挂号" |
| 3 | 排班日历 | 一周 7 天 × 上午/下午的格子，绿色有余号、红色约满、灰色停诊，点格子直接挂号 |
| 4 | 我的预约 | 左边预约记录、右边预约凭证，下面有查看凭证/签到/取消/去评价 |
| 5 | 就诊路线 | 左边平面图（可以切换楼层）、右边文字路线说明 |
| 6 | 候诊队列 | 等候名单、叫下一位、过号、完成就诊 |
| 7 | 通知与评价 | 左边停诊通知、右边给医生打星评价 |

### 里面的函数分三种

**第一种：画图工具函数（所有页面共用）**

| 函数 | 作用 |
|---|---|
| `setFont(size)` | 设字体。统一用宋体，并设成透明背景 |
| `box(x,y,w,h,色)` | 画实心矩形 |
| `frame(x,y,w,h,色)` | 画一个矩形边框 |
| `put(x,y,s,色,字号)` | 写字。**注意：EasyX 的 outtextxy 不认换行符**，所以这个函数自己按 `\n` 一行行画 |
| `putMid(x,y,w,s,色,字号)` | 在矩形宽度里居中写字 |
| `hit(x,y,w,h)` | 判断鼠标点没点在这个矩形里 |
| `btn(x,y,w,h,文字,是否主按钮)` | 画按钮。只画一个方框加一行字，没有悬停效果 |
| `tip(s)` | 在底部提示条显示一句话 |
| `pageTitle(标题,副标题)` | 画页面顶部的标题和说明 |

**第二种：每个页面对应的两个函数**
`drawXxx()` 负责画，`clickXxx(mx,my)` 负责判断点击了哪里。两边用的是**同一套坐标**，所以点得准。

**第三种：辅助和主循环**
`findScheduleOf()` 查某医生某天某时段的排班、`statusName()` 预约状态转中文、
`waitingOf()` 数某医生现在有几个人在等、`pickQueueDoctor()` 没人的时候自动换个医生、
`drawPage()` 统一调页面的绘制、`onClick()` 统一分发点击、`uiMain()` 是主循环。

**第三种：主循环 `uiMain()`**
```
打开窗口
循环：
    处理鼠标移动、点击、按键消息
    重画页面
    刷新显示
    等 20 毫秒
```

### 老师可能问
- **问：界面是怎么做出来的？**
  答：用的是 EasyX 图形库，本质就是在窗口上画矩形和文字。每个页面先画一块块的面板，再往里面填字；按钮就是画一个矩形加一行字。界面故意做得很简单，只有方框和文字，不做动画和渐变。
- **问：点击是怎么判断的？**
  答：每个可点击的地方都知道自己的坐标范围（比如按钮在 x=120, y=132, 宽90, 高30），鼠标点击时用 `hit` 判断点击位置在不在这个范围里，在的话就执行对应的功能。
- **问：为什么 `put` 要自己写而不用 outtextxy？**
  答：因为 EasyX 的 `outtextxy` 不处理换行符，预约凭证和路线说明都是多行文字，直接画会全挤在一行。所以我自己按 `\n` 拆开，一行一行画。
- **问：中文显示是怎么处理的？**
  答：编译时用 `-fexec-charset=GBK` 把字符串常量转成 GBK，字体用宋体。数据文件读进来的时候也会转成 GBK，这样两边一致就不会乱码。

## 7. 老师可能问的整体问题（提前准备）

**Q1：你用到了哪些数据结构？**
> 数组（顺序表）存科室、医生、排班这些数据；邻接矩阵存平面图；用一个按优先级排好序的数组实现候诊队列（相当于优先队列）；字符串匹配是自己写的两层循环。

**Q2：题目说不能用类库和模板，你用了吗？**
> 没用 STL，没用模板，也没用 string 类。数组、查找、排序、图都是自己写的。只用了 C 标准库的 `strcpy`、`sprintf`、`fopen` 这些基础函数，还有 EasyX 图形库（题目允许界面用库）。

**Q3：题目要求科室不少于 10 个、医生不少于 30 人，你做了多少？**
> 科室 12 个，医生 36 个（每个科室 3 名，分别是主任医师、副主任医师、主治医师），排班 264 条。

**Q4：扩展要求做了哪些？**
> 四个都做了：
> ① 候诊队列实时管理（签到进队列、老年人优先、叫号、过号、完成就诊）；
> ② 医生停诊自动通知（停诊时自动退号、退号源、给每位患者发通知，可以在"通知与评价"页点按钮演示）；
> ③ 患者评价（打 1~5 星，评价后医生的平均分会重新计算，导诊时会用上这个评分）；
> ④ 科室间转诊推荐（用余弦相似度算科室相似度，号源紧张时推荐相近的科室）。

**Q5：你的程序有什么不足？以后怎么改进？**
> ① 查找用的是顺序查找，数据量大时慢，可以改成二分查找或哈希表；
> ② 候诊队列用有序数组，插入是 O(n)，人数多时可以用堆优化到 O(log n)；
> ③ Dijkstra 是 O(V²)，可以用最小堆优化成 O((V+E)logV)；
> ④ 数据只在内存里，程序退出后新加的预约和评价不会保存，可以用文件写回。
> ⑤ 没有处理多线程同时预约的情况，真实系统里要给排班加锁。

**Q6：为什么把代码分成这 6 个文件？**
> 按职责分的：数据相关的都放 data.cpp，算法放 graph.cpp，业务逻辑放 logic.cpp，界面放 ui.cpp，公共定义放 structs.h。这样每个文件职责清楚，改一个功能只动一个文件。
