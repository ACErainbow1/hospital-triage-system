## 三、开发中遇到的问题和解决方法

这些都是我写的时候真实碰到的问题，记下来方便以后看。

### 问题 1：界面上的中文全是乱码

**现象**：数据明明读进来了，但界面上显示出来是一堆看不懂的符号。

**原因**：数据文件是我用记事本另存为 **UTF-8** 的，但是程序编译时加了
`-fexec-charset=GBK`，所以程序里的中文字符串是 **GBK** 的，EasyX 显示也是按 GBK。
两边编码不一样，就乱码了。

**解决**：在 `data.cpp` 里写了一个 `utf8ToGbk()` 函数，
读文件的时候把每一行先转成 GBK 再用。转码用的是 Windows 系统的
`MultiByteToWideChar` 和 `WideCharToMultiByte` 两个函数。

**学到**：只要程序里同时有"文件里的文字"和"代码里写死的文字"，就一定要注意编码要一致。

### 问题 2：多行文字挤成了一行

**现象**：预约凭证本来是好几行的，结果界面上全挤在一行里显示，还超出了面板。

**原因**：EasyX 的 `outtextxy()` 函数**不认识换行符 `\n`**，它把整个字符串当成一行画。

**解决**：自己写了一个 `put()` 函数，先用 `\n` 把字符串拆成一行一行的，
再分别调用 `outtextxy()` 画出来。

**学到**：用图形库的时候不能想当然，很多函数的实际行为和想象的不一样，要试一下。

### 问题 3：平面图上的点全挤在一起

**现象**：就诊路线页的平面图，58 个节点密密麻麻叠在一起，完全看不清。

**原因**：一开始我把所有楼层的节点一次性全画出来了。
但是不同楼层的节点坐标是各自独立的（都是 60~560 这种范围），画在一起就重叠了。

**解决**：改成**一次只画一层**，上面加了 1F～6F 的楼层按钮，点哪个就画哪一层。
路线如果跨楼层，画面只画当前这层的那一段，文字说明里会写"坐电梯到 3 层"。

**学到**：画图之前要先把"坐标空间"想清楚。

### 问题 4：候诊队列页打开是空的

**现象**：数据里明明有 6 个人已经签到了，但候诊队列页显示"目前没有人在等"。

**原因**：队列页是按"当前选中的医生"来筛选的，
而默认选中的那个医生（陈志远）恰好没有人排队，人都在别的医生那里。

**解决**：加了一个 `pickQueueDoctor()` 函数，点进队列页的时候，
如果当前医生没有人等，就自动切到一个有患者在等的医生。

**学到**：界面上"看起来是空的"不一定数据错了，可能是筛选条件不合适。

### 问题 5：数据文件里的日期过几天就失效了

**现象**：数据文件里日期是写死的（比如 2026-10-12），
过几天再运行程序，"可以预约的时段"就都变成过去的时间了。

**解决**：数据文件里的日期改成写 `TODAY`、`TODAY+1`、`TODAY-1` 这种形式，
程序启动的时候用 `realDate()` 函数换成真正的今天/明天/昨天。
这样测试数据放多久都不会过期。

**学到**：测试数据要考虑到"什么时候运行"，尽量不要写死跟时间有关的东西。

### 问题 6：停诊通知功能在界面上没办法触发

**现象**：`suspendSchedule()` 函数写好了，但是界面上没有任何按钮能调用它，
演示的时候没法展示这个扩展功能。

**解决**：在"通知与评价"页面加了一个"模拟医生停诊（发通知）"按钮，
点一下就把当前医生一条有预约的排班停掉，系统会自动退号、退号源、给患者发通知。

**学到**：功能写完了还要有入口，不然等于没做。

### 问题 7：双击 exe 运行时报"数据读取失败"

**现象**：在项目根目录用命令行运行 `build\hospital.exe` 一切正常，
但是直接**双击** `build\hospital.exe`，程序弹出一句"数据读取失败，请检查 data 目录下的文件是否存在"。

**原因**：双击 exe 时，程序的**工作目录是 exe 所在的目录**，也就是 `build\`，
而不是项目根目录。我原来在 8 个读文件的函数里都是直接写 `fopen("data/department.txt", "r")`，
这个相对路径是相对工作目录算的，在 `build\` 下就变成了 `build\data\department.txt`，当然找不到。

**解决**：写了一个 `openData()` 函数统一负责打开数据文件：

```c
FILE* openData(const char* name)
{
    char path[80];
    FILE* fp;
    sprintf(path, "data/%s", name);      /* 先按项目根目录下运行来找 */
    fp = fopen(path, "r");
    if (fp == NULL) {
        sprintf(path, "../data/%s", name);   /* 再往上一层找（在 build 里运行时） */
        fp = fopen(path, "r");
    }
    return fp;
}
```

然后把 8 处 `fopen("data/xxx.txt", "r")` 全换成 `openData("xxx.txt")`。
另外加了一个 `run.bat`，双击就能自动编译并运行，不用管工作目录的事。

**验证**：分别在项目根目录、`build` 目录、`C:\Windows\Temp` 三个地方运行，前两个都能正确读出
"科室 12、医生 36、排班 264、平面图 58"，第三个才报错，说明两级查找是有效的。

**学到**：**相对路径是相对"工作目录"的，不是相对 exe 的位置**。
只要程序要读外部文件，就要考虑"用户会从哪里启动它"。

## 五、后续可以改进的地方

1. **查找改成二分或者哈希**：现在全是顺序查找，数据量大了会慢。
2. **候诊队列改成堆**：现在是 O(n) 插入，人多了慢。
3. **Dijkstra 用堆优化**：现在是 O(V²)，可以降到 O((V+E)logV)。
4. **数据保存到文件**：现在新加的预约和评价只在内存里，程序关掉就没了。
5. **多线程安全**：多人同时预约的时候号源可能会冲突，真实系统要给排班加锁。
6. **加上换班功能**：题目扩展要求里提到"停诊或换班"，现在只做了停诊通知，换班还没做。
