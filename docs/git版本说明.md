# Git 版本说明（三次检查分别交什么）

> 这个文件把 git 里的 6 次提交、3 个版本标签详细列出来，
> 方便说明"每一版做到哪一步了""每次提交加了什么"。

---

## 一、总览

```
第六次提交：补充说明文档和界面截图          ← v1.0-final（第15周最终验收）
第五次提交：完成图形界面，程序可以运行了      ← v0.2-midterm2（第11周第二次检查）
第四次提交：完成导诊、预约、候诊队列等业务功能
第三次提交：加入平面图和最短路算法           ← v0.1-midterm1（第6周第一次检查）
第二次提交：定义结构体，把数据文件读进来
第一次提交：写需求分析和数据结构设计
```

> 想直接看某个版本：`git checkout v0.1-midterm1`，
> 看完一定要 `git checkout main` 切回来。

| 提交 | 加了哪些文件 | 增加行数 | 能否编译运行 |
|---|---|---|---|
| 第 1 次 | 2 个文档 + 2 个 git 配置 | 404 | 没有代码，不能 |
| 第 2 次 | `structs.h`、`data.cpp`、8 个数据文件 | 1307 | 还没有 main，不能 |
| 第 3 次 | `graph.cpp` | 141 | 还没有 main，不能 |
| 第 4 次 | `logic.cpp` | 515 | 还没有 main，不能 |
| 第 5 次 | `ui.cpp`、`main.cpp`、`build.bat` | 1108 | **能编译能运行了** |
| 第 6 次 | README、4 个文档、9 张截图 | 1003 | 能 |

> 为什么前几次不能运行：因为 `main.cpp` 是最后才写的。
> 整个程序要到**第五次提交**才第一次能跑起来。这是很正常的开发顺序。

## 四、怎么查看和切换版本

```bash
git log --oneline --decorate        # 看提交记录，标签会标出来
git tag                             # 列出所有标签
git show v0.1-midterm1 --stat       # 看这个版本提交了哪些文件

git checkout v0.1-midterm1          # 切到第一次检查的版本（看代码会变少）
git checkout v0.2-midterm2          # 切到第二次检查的版本
git checkout v1.0-final             # 切到最终版
git checkout main                   # ★ 看完一定要切回来
```

> **重要提醒**：`git checkout 标签名` 之后，git 会进入"分离头指针"（detached HEAD）状态。
> 这时候 `src/` 目录里的文件会变成那个版本的样子（比如切到 v0.1 就只剩 3 个源文件）。
> **这不是文件丢了**，切回 `main` 就全回来了。
> ```
> git checkout main     ← 记住这一句
> ```
