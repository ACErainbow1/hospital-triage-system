## 一、总体思路

程序里所有的数据都放在**全局数组**里，用"数组 + 个数变量"的方式来管：

```c
Dept   depts[20];     int deptNum = 0;      /* 科室，最多 20 个 */
Doctor doctors[60];   int doctorNum = 0;    /* 医生，最多 60 个 */
```

这样写的好处是简单直接：用 `depts[i]` 就能拿到第 i 个科室，
其它函数要用数据的话，因为数组是全局的，直接就能访问，不用一层层传参数。

## 二、结构体设计

| 结构体 | 说明 |
|---|---|
| `Dept` | 科室：编号、名称、位置、楼层、简介、常见症状 |
| `Doctor` | 医生：编号、姓名、科室、职称、擅长、挂号费、评分、**诊室节点号** |
| `Schedule` | 排班：编号、医生、日期、时段(1上午 2下午)、最多几个、已约几个、状态(0正常 1停诊) |
| `Patient` | 患者：编号、姓名、性别、年龄、手机、密码 |
| `Appointment` | 预约：编号、患者、医生、排班号、第几号、状态 |
| `Evaluation` | 评价：编号、患者、医生、分数、内容 |
| `Symptom` | 症状—科室关联：症状词、科室、关联强度（**二部图的边**） |
| `MapNode` | 平面图节点：编号、楼层、名称、类型、科室、医生、坐标 |
| `QueueItem` | 候诊队列项：预约号、优先级 |
| `Notice` | 通知：患者、内容 |

**预约的状态**用了 7 个数字表示：

```
0 已预约 → 签到 → 1 已签到 → 叫号 → 2 就诊中 → 完成 → 3 已完成 → 可以评价
   ↓                    ↓
 4 已取消            5 爽约（过号）
   ↓
 6 停诊退号
```

## 三、用到的数据结构

### 3.1 数组（顺序表）

**用在哪**：科室表、医生表、排班表、患者表、预约表、评价表、平面图节点表。

**为什么**：这些数据条数不多（最多几百条），而且经常需要"按顺序全部遍历一遍"，
数组支持随机访问 `a[i]`，是最合适的。

**查找**：用顺序查找，从头到尾比一遍。

```
时间复杂度：查找 O(n)，插入到末尾 O(1)
```

> 如果数据量大，可以先把数组按编号排好序，然后改成**二分查找**，
> 查找就变成 O(log n) 了。这是可以改进的地方。

### 3.2 邻接矩阵（图）

**用在哪**：就诊楼的平面图。

**怎么存**：

```c
int graph[120][120];      /* graph[i][j] = i 到 j 的距离，0 表示不通 */
int edgeKind[120][120];   /* 这条边的类型：0走廊 1电梯 2楼梯 */
```

**为什么用邻接矩阵不用邻接表**：
- 节点只有 58 个，120×120 的二维数组才占 57KB，内存完全够；
- Dijkstra 算法里要频繁判断"u 和 v 之间通不通"，用矩阵写 `graph[u][v]` 就是 O(1)；
- 用邻接表的话代码要写链表，麻烦，而这里节点少，省不下多少内存。

> 如果节点有几千个，就应该换成邻接表，省内存。

**图的构成**：
- 每个楼层内部的走廊、诊室用边连起来；
- 电梯在每层有一个节点，一层电梯连二层电梯，二层连三层……边长固定 5 米；
- 楼梯也一样。这样 6 层楼就被连成了一张连通图。

### 3.3 有序数组（当优先队列用）

**用在哪**：候诊队列。

**怎么做的**：普通队列是"先来先服务"，但医院里老年人应该优先看，
所以需要按优先级排队。做法是**插入的时候就插到正确的位置**：

```c
void queueInsert(int apptId, int priority)
{
    int i = queueNum;
    while (i > 0 && queueData[i-1].priority > priority) {
        queueData[i] = queueData[i-1];    /* 比它优先级低的往后挪一个位置 */
        i--;
    }
    queueData[i].apptId  = apptId;
    queueData[i].priority = priority;
    queueNum++;
}
```

这样数组的第 0 个永远是最该先看的人，叫号的时候直接取第 0 个就行。

**优先级怎么定的**：年龄 ≥ 65 岁的患者是 2，其他人是 3。数字小的排前面。

```
插入：O(n)    叫号（取第一个）：O(1)
```

> 如果排队的人很多（几百个），可以用**二叉堆**来做优先队列，
> 插入和取出都只要 O(log n)。本项目同时最多几十个人排队，用有序数组足够。

### 3.4 二维数组（日历）

**用在哪**：排班日历页。

显示的是"7 天 × 上午/下午"的表格，每画一个格子就去查这个医生那天的排班。
查的时候用 `findScheduleOf(医生, 日期, 时段)` 遍历一遍排班表。

> 也可以像哈希表那样按"医生+日期+时段"直接算出位置，省掉遍历，但数据量小，不值得。

## 四、核心算法

### 4.1 智能导诊（加权二部图）

**模型**：症状在一边，科室在另一边，如果某个症状和某个科室有关系，就在它们之间连一条边，
边上的权表示关系有多强。

```
   症状（左）                      科室（右）
   胸闷 ──────────0.90──────────→ 心血管内科
     └──────────0.30──────────→ 呼吸内科
   心悸 ──────────0.87──────────→ 心血管内科
   反酸 ──────────0.85──────────→ 消化内科
   ...
```

**算法步骤**：

```
第一步：在患者输入的文字里找症状关键词
        用自己写的 findWord()，两层循环逐个字符比
第二步：每个命中的症状词，把它的边权加到对应科室的得分上
第三步：加上加成
        评分加成 = 科室平均分 / 5 × 1.5      （最多 1.5 分）
        号源加成 = min(未来3天余号, 30) / 30  （最多 1 分）
第四步：找出最高分，把每个科室的得分换算成百分比
        匹配度 = 得分 / 最高分 × 100%
第五步：选择排序，从高到低取前 8 个
```

**如果一个症状词都没认出来怎么办**：先退一步，拿输入的文字去和科室的"常见症状"字段做比对；
要是还是全 0，就直接按科室评分排序，保证无论如何都能给出推荐结果。

### 4.2 就诊路线（Dijkstra 最短路）

**问题**：从门诊大门到某个医生的诊室，怎么走最近？

**算法**：Dijkstra 算法。

```
dist[]    起点到每个点的当前最短距离
visited[] 哪些点已经确定了
prev[]    记录每个点是从哪走过来的

1. dist[起点] = 0，其它都是无穷大
2. 重复：
   a. 在"还没确定"的点里，找一个 dist 最小的，叫做 u
   b. 如果 u 就是终点，结束
   c. 用 u 去更新它周围的点 v：
        如果 dist[u] + graph[u][v] < dist[v]，就更新 dist[v] 和 prev[v]
3. 从终点沿着 prev[] 倒着走回起点，就得到路径了
```

**复杂度**：O(V²)。本项目的图只有 58 个节点，58² = 3364，非常快。

> 改进方向：用最小堆来选那个 dist 最小的点，复杂度能降到 O((V+E)logV)。

### 4.3 科室相似度（余弦相似度）

转诊推荐的时候要判断两个科室"像不像"。把每个科室看成由"症状权重"组成的一个向量，
然后用余弦相似度：

```
sim(A, B) = (A · B) / (|A| × |B|)
```

- 分子：A 和 B 在同一个症状上的权重相乘，再全部加起来
- 分母：A 向量长度 × B 向量长度

**推荐度的计算公式**：

```
推荐度 = 相似度 × 60 + 余号充裕度 × 25 + 科室评分/5 × 15
```

而且只推荐**未来 3 天还有号**的科室。

### 4.4 日期计算

**求星期几**用基姆拉尔森公式：

```
把 1 月、2 月看成上一年的 13 月、14 月
w = (d + 2m + 3(m+1)/5 + y + y/4 - y/100 + y/400) % 7
结果是 0=周一 1=周二 … 5=周六 6=周日
```

**日期加减**就用最笨的办法：一天一天地加，日数超过当月天数就月份加 1，
月份超过 12 就年份加 1（减的时候反过来）。闰年 2 月 29 天。

> 这种写法虽然不够快（加 n 天要循环 n 次），但是最容易看懂。反正 n 最多也就几十。

## 五、复杂度汇总

| 操作 | 复杂度 | 用什么实现的 |
|---|---|---|
| 按编号查科室/医生/排班 | O(n) | 顺序查找 |
| 智能导诊 | O(症状数 × 关联边数) | 二部图 + 简单匹配 |
| 求最短路 | O(V²) | 邻接矩阵 + Dijkstra |
| 预约挂号 | O(n)（查重复预约） | 数组遍历 |
| 签到进队列 | O(n) | 有序数组插入 |
| 叫下一位 | O(n) | 数组元素前移 |
| 求科室相似度 | O(关联边数²) | 余弦相似度 |
| 排班日历查格子 | O(排班数) | 遍历 |

## 六、为什么这样选（老师可能问）

| 问题 | 回答 |
|---|---|
| 为什么用全局数组，不用链表？ | 数据条数固定而且不多，数组访问快、写起来简单。链表适合频繁在中间插入删除的情况，这里用不上。 |
| 为什么图用邻接矩阵不用邻接表？ | 节点只有 58 个，矩阵占不了多少内存，而且判断两点是否相连是 O(1)，Dijkstra 里要用到。节点多了才该用邻接表。 |
| 候诊队列为什么不用队列（先进先出）？ | 因为要按优先级出队，老年人优先，不是严格先来先服务，所以用有序数组来实现优先队列。 |
| 查找为什么用顺序查找？ | 数据量小，顺序查找简单可靠。数据量大了可以排序后二分查找。 |
| 有没有可以改进的地方？ | 有：① 查找可以改二分或者哈希；② 候诊队列可以改堆；③ Dijkstra 可以用堆优化；④ 数据没有保存到文件，退出就没了。 |
